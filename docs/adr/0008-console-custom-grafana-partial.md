# ADR-008: 관제 콘솔은 전 화면 자체 구현하되 비용·지연 시계열만 Grafana 패널을 임베드한다

| 항목 | 값 |
| --- | --- |
| **상태** | 수락됨 |
| **날짜** | 2026-10-18 |
| **작성자** | `AI-SVC` |
| **검토자** | `AI-MDL` |

---

## 컨텍스트

콘솔은 7개 화면이고 두 파트가 나눠 구현한다. 핵심 화면인 환각 구간 하이라이트, 인시던트 타임라인 위 변경 이력 겹침, 에이전트 조사 과정 노출은 범용 대시보드 도구의 패널로는 표현할 수 없다. 반면 비용·지연 시계열은 이미 Prometheus에 수집되어 Grafana에서 바로 그릴 수 있는 형태다. 2인 팀에서 프론트엔드 작업량은 일정 리스크 1순위다.

## 결정 근거

- 핵심 화면의 표현 가능 여부.
- 프론트엔드 작업량 절감.
- 인증 경계의 단순성(이중 로그인 회피).
- 디자인 일관성.

## 고려한 옵션들

- 옵션 1: 전 화면 자체 구현
- 옵션 2: 전면 Grafana 대시보드
- 옵션 3: 자체 구현 + 비용·지연 시계열만 Grafana 패널 임베드

## 결정

옵션 3 **자체 구현 + 부분 임베드**를 선택한다. 차별점을 이루는 화면들은 자체 구현 외에 방법이 없지만, 이미 Grafana에 존재하는 비용·지연 시계열까지 다시 그리는 것은 순수한 중복 작업이다. 임베드 패널은 읽기 전용으로 공유하고 콘솔 로그인 뒤에서만 노출하여, 사용자가 Grafana에 별도로 로그인하지 않게 한다.

## 결과

**긍정적**

- 프론트엔드 작업량이 줄어 SP2 일정 리스크가 완화된다.
- 핵심 화면은 제약 없이 설계할 수 있다.
- 사용자는 로그인 한 번으로 모든 화면을 본다.

**부정적**

- 임베드 패널과 자체 화면의 디자인 톤이 달라진다.
- Grafana 공유 설정이 잘못되면 인증 우회 경로가 생길 수 있다.

**후속 작업**

- Grafana 익명 열람 범위와 임베드 허용 도메인 설정 점검
- 대시보드 JSON을 저장소에 코드로 관리(Provisioning)
- 임베드 영역의 테마를 콘솔과 맞추는 최소 작업

## 옵션별 장단점

### 옵션 1 — 전 화면 자체 구현

- 장점: 디자인과 인증 경계가 완전히 일관된다.
- 단점: 이미 존재하는 시계열 패널을 다시 만들어야 해 2인 팀 일정에 부담이다.

### 옵션 2 — 전면 Grafana

- 장점: 프론트엔드 구현이 거의 없다.
- 단점: 환각 하이라이트·타임라인 겹침·조사 과정 노출이 불가능해 핵심 가치가 사라진다.

### 옵션 3 — 자체 구현 + 부분 임베드 (채택)

- 장점: 표현력과 작업량을 둘 다 확보한다.
- 단점: 디자인 이질감과 임베드 보안 설정 점검 부담이 있다.

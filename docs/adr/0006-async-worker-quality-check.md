# ADR-006: 품질 검사는 요청 경로에서 분리한 비동기 워커에서 준실시간 + 배치로 수행한다

| 항목 | 값 |
| --- | --- |
| **상태** | 수락됨 |
| **날짜** | 2026-10-16 |
| **작성자** | `AI-SVC` |
| **검토자** | `AI-MDL` |

---

## 컨텍스트

1단계 탐지는 모든 응답을 검사하므로, 이를 요청 처리 중에 동기로 수행하면 사용자 응답 지연이 검사 시간만큼 늘어난다. 반대로 하루 단위 배치로만 돌리면 "변경 직후 품질 그래프가 내려가는" 시연과 5분 창 드리프트 감지가 성립하지 않는다. 1단계 모델은 CPU에서 돌기 때문에 건별 추론보다 배치 추론이 처리량 면에서 유리하다.

## 결정 근거

- 감시 대상 서비스의 응답 지연에 주는 영향.
- 드리프트 감지(5분 창)와 시연에 필요한 반응 속도.
- CPU 추론 효율(배치 크기와 처리량의 관계).
- 구현 복잡도.

## 고려한 옵션들

- 옵션 1: 요청 처리 중 동기 검사
- 옵션 2: 일/시간 단위 배치 검사
- 옵션 3: 비동기 워커 + 준실시간 배치(N건 또는 T초 중 먼저 도달한 조건)

## 결정

옵션 3 **비동기 워커의 준실시간 배치(초기값 N=16, T=2초)**를 선택한다. 품질 감시의 목적은 사후 관측이므로 사용자 응답을 지연시킬 이유가 없고, 동시에 5분 창 드리프트 판정과 발표 시연에는 수 초 수준의 반응 속도가 필요하다. N과 T를 설정값으로 두어 배치 크기–지연 곡선을 실험으로 조정할 수 있게 한다.

## 결과

**긍정적**

- 계측·검사가 사용자 응답 경로 밖에 있어 관측이 서비스 성능을 해치지 않는다.
- 배치 추론으로 CPU 처리량이 올라가 t3.large에서 전수 검사가 현실적인 선택이 된다.
- 워커를 수평으로 늘리면 처리량을 확장할 경로가 열려 있다.

**부정적**

- 검사 결과가 응답보다 수 초 늦게 나오므로 실시간 차단(가드레일) 용도로는 쓸 수 없다.
- 배치 경계 때문에 트래픽이 희박할 때 최대 T초의 고정 지연이 생긴다.

**후속 작업**

- N·T 기본값 확정을 위한 배치 크기별 처리량–지연 측정 (8.1 성능)
- 워커 재기동 중 미처리 작업 재개 테스트 (8.2-3)
- 실시간 차단은 범위 외임을 기획서 5.3에 명시 — 완료

## 옵션별 장단점

### 옵션 1 — 동기 검사

- 장점: 결과가 응답과 함께 나와 차단·재생성 같은 즉시 조치가 가능하다.
- 단점: 사용자 응답 지연이 검사 시간만큼 직접 증가한다.
- 단점: 검사 장애가 서비스 장애로 전이된다.

### 옵션 2 — 대형 배치

- 장점: 추론 효율이 가장 좋고 구현이 단순하다.
- 단점: 탐지 지연이 시간 단위가 되어 5분 창 드리프트 감지와 시연이 불가능하다.

### 옵션 3 — 준실시간 배치 (채택)

- 장점: 지연 영향 없이 수 초 내 결과를 얻어 감지·시연 요건을 함께 만족한다.
- 단점: 배치 경계 관리와 워커 상태 처리 로직이 필요하다.

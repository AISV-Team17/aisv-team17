# ADR-002: OTel GenAI 시맨틱 컨벤션 버전을 고정하고 자체 속성은 매핑 계층으로 분리한다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락됨 |
| 날짜 | 2026-10-14 |
| 작성자 | `AI-SVC` |
| 검토자 | `AI-MDL` |

---

## 컨텍스트

계측 속성 이름을 자체적으로 정하면 다른 관측 도구와 호환되지 않고, 표준을 그대로 따르면 아직 Development 단계인 OpenTelemetry GenAI 시맨틱 컨벤션의 변경에 계측 코드가 통째로 휘둘린다. 이 규약은 2026년 6월 별도 저장소로 분리되었고 `gen_ai.*` 속성 대부분이 아직 안정 단계가 아니다. 한편 우리에게 꼭 필요한 프롬프트·검색 설정 버전과 요청 단위 비용은 표준에 정의되어 있지 않아 자체 속성이 불가피하다.

## 결정 근거

- 다른 관측 도구와의 호환성(도구 종속 회피).
- 표준 변경 시 수정 범위의 국소성.
- 자체 속성과 표준 속성의 책임 분리 명확성.

## 고려한 옵션들

- 옵션 1: 자체 속성 체계만 사용
- 옵션 2: OTel GenAI 최신판을 항상 추종
- 옵션 3: 표준 버전을 고정하고, 자체 속성은 `app.*` 네임스페이스로 분리하며 그 사이에 매핑 계층을 둔다

## 결정

옵션 3 **버전 고정 + `app.*` 네임스페이스 분리 + 매핑 계층**을 선택한다. 표준을 따라야 도구 독립성이라는 주장을 유지할 수 있지만, 아직 변하는 중인 규약을 직접 추종하면 실험 기간 중 계측 코드가 흔들려 수집된 데이터의 비교 가능성이 깨진다. 고정된 버전을 기준으로 삼고 매핑 계층 한 곳만 고치면 되도록 하여, 표준 변경의 영향을 코드 한 지점에 가둔다.

## 결과

**긍정적**

- `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.usage.*` 등 표준 속성을 쓰므로 Phoenix 등 다른 백엔드로도 그대로 보낼 수 있다.
- 표준이 바뀌어도 `app.version.*`, `app.cost.usd` 같은 자체 속성은 영향을 받지 않는다.
- 실험 전 구간에서 속성 이름이 고정되어 시계열 비교가 깨지지 않는다.

**부정적**

- 고정한 버전이 낡으면 나중에 한 번은 마이그레이션해야 한다.
- 매핑 계층이라는 간접층이 하나 늘어난다.

**후속 작업**

- 적용 컨벤션 버전을 `src/sdk/semconv.py` 상수와 이 ADR에 함께 명시
- `app.*` 속성 목록을 API 명세 문서에 정리
- SP3 종료 후 표준 변경분 재검토

## 옵션별 장단점

### 옵션 1 — 자체 속성만 사용

- 장점: 설계가 자유롭고 초기 구현이 가장 단순하다.
- 단점: 다른 관측 도구로 보낼 수 없어 "도구에 묶이지 않는다"는 차별점 주장이 무너진다.

### 옵션 2 — 최신 표준 추종

- 장점: 항상 최신 호환성을 유지한다.
- 단점: Development 단계 속성이 바뀌면 실험 중간에 데이터 스키마가 달라져 구간 비교가 불가능해진다.

### 옵션 3 — 버전 고정 + 매핑 계층 (채택)

- 장점: 호환성과 안정성을 동시에 얻고, 변경 영향이 한 파일에 갇힌다.
- 단점: 간접층 유지 비용과 주기적 버전 업 작업이 생긴다.

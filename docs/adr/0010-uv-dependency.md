## 컨텍스트

같은 코드가 로컬 노트북, GitHub Actions, Docker 이미지, Colab 실험 환경에서 각각 실행된다. 특히 모델 추론 결과와 지연 측정치는 라이브러리 버전에 민감하므로, 환경 간 버전이 어긋나면 실험 결과의 재현성이 깨진다.

## 결정 근거

- 환경 간 재현성(lock 파일 지원).
- 설치·해결 속도(CI 시간과 Docker 빌드 시간).
- 학습 비용과 도구 성숙도.

## 고려한 옵션들

- 옵션 1: pip + `requirements.txt`
- 옵션 2: Poetry
- 옵션 3: uv

## 결정

옵션 3 **uv**를 선택한다. `uv.lock`으로 개발·CI·Docker의 의존성 집합을 정확히 일치시킬 수 있고, 해결·설치 속도가 빨라 CI와 이미지 빌드 시간이 짧아진다. `requirements.txt`는 전이 의존성 고정이 불완전해 재현성 요구를 만족하지 못한다.

## 결과

**긍정적**

- 실험 환경과 서빙 환경의 라이브러리 버전이 일치해 측정값 비교가 유효해진다.
- CI·Docker 빌드 시간이 단축된다.

**부정적**

- 비교적 새로운 도구라 레퍼런스가 Poetry·pip보다 적다.
- Colab 등 외부 환경에서는 별도 설치 단계가 필요하다.

**후속 작업**

- `pyproject.toml` + `uv.lock` 커밋, lock 갱신 규칙 정의
- Dockerfile과 CI 캐시 전략 적용
- 실험 노트북용 설치 스니펫을 `experiments/README`에 추가

## 옵션별 장단점

### 옵션 1 — pip + requirements.txt

- 장점: 가장 익숙하고 어디서나 동작한다.
- 단점: 전이 의존성까지 고정하려면 별도 도구가 필요해 재현성이 약하다.

### 옵션 2 — Poetry

- 장점: lock 파일을 제공하고 레퍼런스가 많다.
- 단점: 의존성 해결이 느려 CI·빌드 시간이 길어진다.

### 옵션 3 — uv (채택)

- 장점: lock 기반 재현성과 빠른 설치를 모두 제공한다.
- 단점: 생태계 성숙도가 상대적으로 낮다.

# ADR-028: 과제 A의 개선 축을 정확도가 아닌 추론 효율(크기·지연)로 설정한다

| 항목 | 값 |
| --- | --- |
| **상태** | 수락됨 |
| **날짜** | 2026-10-24 |
| **작성자** | `AI-MDL` |
| **검토자** | `AI-SVC` |

---

## 컨텍스트

2인 팀, SP2(11/18)·SP3(12/09) 일정, 단일 CPU 서버라는 조건에서 "정확도로 최신 모델을 넘는다"는 목표는 현실적이지 않다. LettuceDetect보다 정확도가 높은 공개 결과(RAG-HAT, 8B)가 이미 있고, 그 방향은 GPU 서빙이 필요하다. 모델 연구 결과가 서비스 운영 비용으로 바로 이어지는 축을 골라야, 플랫폼과 연구가 따로 놀지 않는다. 결과는 학술제 출품과 논문 투고로 이어진다.

## 결정 근거

- 정확도 향상 축: 8B LLM 미세조정 결과가 이미 공개되어 있어 인코더 방식으로 넘기 어렵다.
- 추론 효율 축: 1단계 CPU 전수 검사라는 시스템 요구와 직결되어 서비스 운영 비용에 바로 반영된다.
- 기준선을 못 넘더라도 정확도–효율 곡선으로 결과가 성립한다.
- 2단 구조 분석(과제 B)은 1단계 모델 성능과 독립적으로 성립하므로, 과제 A 결과가 약해도 전체 연구가 무너지지 않는다.

## 고려한 옵션들

- 옵션 1: 정확도 향상 (기준선 F1 넘기기)
- 옵션 2: 다국어(한국어) 확장
- 옵션 3: 추론 효율 (크기·지연) — 정확도 손실을 최소화하며 CPU 지연·모델 크기 축소

## 결정

옵션 3 **추론 효율**을 과제 A의 개선 축으로 설정하고, 각 과제의 개선 축과 기준선을 다음과 같이 정한다.

| 과제 | 개선 축 | 기준선 | 핵심 결과물 | 논문 기여 |
| --- | --- | --- | --- | --- |
| A. 경량 환각 탐지 모델 | 추론 효율(크기·지연) | LettuceDetect (PyTorch FP32, CPU) | 정확도–효율 곡선 (F1 vs CPU p95 지연·크기) | C1 |
| B. 채점자 신뢰도 + 2단 라우팅 | 비용–정확도 균형 | LLM 단독 전수 채점 | 채점자–사람 일치도, (τ, r)별 비용·정확도 유지율·누락률 곡선 | C2 |
| C. 품질 저하 탐지 | 탐지 지연 ↔ 오탐률 상충 관계 정량화 | 고정 임계값 | 3방식 × 시간 창별 탐지율·탐지 지연·오탐 횟수 | C3 |
| D. 원인 변경 탐지 (평가 설계) | 규칙 기반 대비 정확도 | 직전 변경 지목(규칙 기반) | Top-1·Top-3 정확도, 근거 정확성, 조사 비용 | C3 |

## 결과

**긍정적**

- 과제 A의 성공 기준이 "기준선 F1 초과"가 아니라 정확도–효율 곡선 제시이므로, 기준선 미달 시에도 결과를 방어할 수 있다.
- 1단계 CPU 전수 검사라는 시스템 요구와 모델 연구가 같은 방향을 가리킨다.
- 각 과제의 결과물(곡선, 정확도)이 실험 화면(채점자 신뢰도·라우팅 정책·A/B 비교)과 논문에 그대로 쓰인다.

**부정적**

- 정확도 최고 기록(SOTA) 달성은 비목표이므로, 학술적 주목도가 낮을 수 있다.
- 한국어 환각 탐지는 이번 범위에서 증명되지 않는다.

**후속 작업**

- 과제 B의 라우팅 실험 분담 경계(`AI-SVC` 구현·실험, `AI-MDL` 분석·보정·화면)를 `protocol.md`에서 확정
- 지연 측정 조건(EC2 t3.large, 예열·반복 횟수)을 `protocol.md`에 고정

## 옵션별 장단점

### 옵션 1 — 정확도 향상

- 장점: 논문에서 가장 직접적인 성과 지표다.
- 단점: 더 높은 공개 결과(RAG-HAT 83.9%)가 이미 있고 GPU 서빙 방향이라, 8주 일정·자원 안에서 넘기 어렵다.

### 옵션 2 — 다국어(한국어) 확장

- 장점: 차별점이 분명하다.
- 단점: 한국어 학습 데이터·기준선이 없고, 서비스 언어가 영어로 결정되었다(ADR-016).

### 옵션 3 — 추론 효율 (채택)

- 장점: 시스템 요구와 직결, 기준선 미달 시에도 결과 성립.
- 단점: 학술적 주목도가 정확도 향상보다 낮을 수 있다.

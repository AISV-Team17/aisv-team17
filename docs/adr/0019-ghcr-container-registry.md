# ADR-019: 컨테이너 레지스트리는 Docker Hub 대신 GHCR을 사용한다

## 컨텍스트

CI는 GitHub Actions에서 돌고, 빌드한 이미지를 EC2가 받아 배포한다. 템플릿 기본값은 Docker Hub이지만, 별도 계정·토큰 관리가 필요하고 무료 플랜에는 이미지 보존·요청 제한이 있다.

## 결정 근거

- CI 인증 구성의 단순성.
- 비용과 사용량 제한.
- 접근 권한 관리(저장소 권한과의 일치).

## 고려한 옵션들

- 옵션 1: Docker Hub
- 옵션 2: GitHub Container Registry (GHCR)
- 옵션 3: AWS ECR

## 결정

옵션 2 **GHCR**을 선택한다. GitHub Actions의 `GITHUB_TOKEN`으로 바로 인증되어 별도 비밀값을 만들 필요가 없고, 저장소 권한 체계를 그대로 따르므로 팀원 권한 관리가 자동으로 일치한다. ECR은 AWS 자격 증명 구성이 추가로 필요하고, 이번 규모에서 얻는 이점이 없다.

## 결과

**긍정적**

- CI에 레지스트리용 비밀값을 추가하지 않아도 된다.
- 저장소와 이미지 권한이 한 곳에서 관리된다.
- Docker Hub의 요청 제한 영향을 받지 않는다.

**부정적**

- EC2에서 비공개 이미지를 받으려면 토큰 또는 공개 설정이 필요하다.
- GitHub 장애 시 배포도 함께 막힌다.

**후속 작업**

- 이미지 태그 규칙(`sha-<커밋>` + `latest`) 정의
- EC2 pull용 토큰을 SSM Parameter Store에 보관 (ADR-021)

## 옵션별 장단점

### 옵션 1 — Docker Hub

- 장점: 가장 보편적이고 문서가 많다.
- 단점: 계정·토큰을 따로 관리해야 하고 무료 플랜 제한이 있다.

### 옵션 2 — GHCR (채택)

- 장점: CI 인증이 기본 제공되고 권한이 저장소와 일치한다.
- 단점: GitHub 종속성이 커진다.

### 옵션 3 — ECR

- 장점: EC2와 같은 AWS 안에 있어 네트워크상 가깝다.
- 단점: 자격 증명·수명주기 정책 구성이 추가로 필요하다.

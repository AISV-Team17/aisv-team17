# ADR-007: 원인 분석 에이전트는 프레임워크 대신 직접 루프로 구현하고 MCP 도구를 조회 전용으로 제한한다

| 항목 | 값 |
| --- | --- |
| **상태** | 수락됨 |
| **날짜** | 2026-10-18 |
| **작성자** | `AI-SVC` |
| **검토자** | `AI-MDL` |

---

## 컨텍스트

품질 저하가 감지되면 에이전트가 변경 이력·트레이스·채점 결과를 조사해 원인 후보를 제시한다. 이 결과는 Top-1·Top-3 정확도로 평가되므로 출력 구조가 고정되어야 하고, 조사 과정 자체가 인시던트 상세 화면의 "조사 과정" 섹션으로 노출되므로 도구 호출 기록이 그대로 남아야 한다. 또한 LLM 에이전트는 반복 호출로 비용이 폭주할 위험이 있고, 쓰기 권한을 가지면 오판이 서비스 변경으로 이어진다.

## 결정 근거

- 호출 횟수·토큰 상한을 코드로 통제할 수 있는지.
- 조사 과정 로그를 화면에 그대로 쓸 수 있는지.
- 오판의 피해 범위 제한(권한 최소화).
- 동작 원리를 팀이 설명할 수 있는지(평가 기준과 직결).

## 고려한 옵션들

- 옵션 1: LangGraph 등 에이전트 프레임워크 사용
- 옵션 2: 직접 구현한 루프 + MCP 조회 전용 도구
- 옵션 3: 규칙 기반 원인 지목만 사용 (직전 변경 지목)

## 결정

옵션 2 **직접 구현 루프 + MCP 조회 전용 도구**를 선택한다. 호출 횟수·토큰 상한, 도구 호출 기록, 결론 JSON 검증이 모두 평가·화면·예산 요건과 직접 연결되어 있어 코드로 쥐고 있어야 한다. 규칙 기반(옵션 3)은 버리지 않고 **상한 도달 시 폴백이자 성능 비교 기준선**으로 함께 유지한다. DB는 read-only 계정으로만 접근하여, 오판이 조사 결과 제시에서 멈추고 서비스 상태를 바꾸지 못하게 한다.

## 결과

**긍정적**

- `MAX_STEPS`·`TOKEN_BUDGET`으로 비용 상한이 보장되고, 상한 도달 시에도 규칙 기반 결과로 데모 흐름이 끊기지 않는다.
- 도구 호출·결과 로그가 그대로 인시던트 상세의 조사 과정이 되어 사람이 결론을 검증할 수 있다.
- 조회 전용 권한이라 자동 롤백 같은 위험한 부작용이 구조적으로 불가능하다.

**부정적**

- 재시도·상태 관리·메시지 누적 제어를 직접 구현해야 한다.
- 프레임워크가 제공하는 고급 플래닝 기능은 쓰지 못한다.

**후속 작업**

- MCP 도구 5종 정의: `list_version_changes`, `get_quality_timeseries`, `compare_versions`, `search_traces`, `get_judge_feedback` (T1-19)
- 결론 JSON 스키마 확정과 검증 실패 시 1회 재시도 정책 (T1-20)
- DB read-only 계정 권한 테스트 (8.2-10)

## 옵션별 장단점

### 옵션 1 — 에이전트 프레임워크

- 장점: 도구 호출·상태 관리·재시도가 이미 구현되어 개발 속도가 빠르다.
- 단점: 내부 동작이 추상화되어 호출·토큰 상한 통제와 로그 포맷을 원하는 대로 맞추기 어렵다.
- 단점: 발표에서 "왜 이렇게 동작하는가"를 설명하기 어려워진다.

### 옵션 2 — 직접 루프 + MCP 조회 전용 (채택)

- 장점: 상한·로그·출력 구조를 전부 통제하고, 그대로 평가 지표와 화면에 연결된다.
- 장점: MCP 서버 경계가 권한 제한 지점 역할을 겸한다.
- 단점: 루프·재시도·토큰 관리 코드를 직접 작성하고 테스트해야 한다.

### 옵션 3 — 규칙 기반 단독

- 장점: 구현이 단순하고 비용이 0이며 결과가 결정적이다.
- 단점: 디코이 변경이 섞이면 정확도가 급락하고, 근거를 서술할 수 없다. 다만 기준선으로서의 가치는 크다.

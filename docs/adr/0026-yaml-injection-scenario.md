# ADR-026: 품질 저하 주입은 코드 수정이 아니라 YAML 시나리오 + 런타임 설정 교체로 수행한다

| 항목 | 값 |
| --- | --- |
| **상태** | 제안됨 |
| **날짜** | 2026-10-25 |
| **작성자** | `AI-SVC` |
| **검토자** | `AI-MDL` |

---

## 컨텍스트

드리프트 탐지와 원인 지목의 정확도를 측정하려면 "언제 무엇이 바뀌었는지"가 확정된 정답 라벨이 필요하다. 주입 실험은 시나리오 5종 × 10회를 반복하며, 각 회차는 같은 질문 집합·같은 시드로 재현되어야 한다. 또 발표에서는 버튼 한 번으로 주입이 실행되어야 한다.

## 결정 근거

- 정답 라벨의 정확성(주입 시점·내용이 기록되는가).
- 재현성(시드·질문 집합 고정).
- 실험 반복 비용(코드 변경 없이 반복 가능한가).
- 시연 조작의 단순성.

## 고려한 옵션들

- 옵션 1: 실험마다 코드를 수정하고 재배포
- 옵션 2: Git 커밋으로 `configs/`를 바꾸고 재배포(실제 배포 흐름과 동일)
- 옵션 3: YAML 시나리오 파일 + 트래픽 생성기 + 런타임 설정 교체

## 결정

옵션 3 **YAML 시나리오 + 런타임 설정 교체**를 선택한다. 주입 시점과 변경 내용을 선언적으로 적어 두면 그 파일 자체가 정답 라벨이 되고, 시드·질문 집합·rps를 함께 고정해 회차 간 재현성을 확보할 수 있다. 런타임 교체도 `version_changes`에 `source=injection`으로 기록되므로(ADR-005) 추적성은 동일하게 유지된다.

## 결과

**긍정적**

- 시나리오 파일이 곧 정답 라벨이라 채점 자동화가 가능하다.
- 같은 시드로 재실행하면 질문 순서와 주입 시점이 재현된다(T1-15 인수 기준).
- 시연에서는 같은 메커니즘을 버튼으로 호출해 흐름이 끊기지 않는다.

**부정적**

- 런타임 설정 교체 경로가 실제 배포 경로와 달라, 배포 시 발생하는 부수 효과(캐시 초기화 등)는 재현되지 않는다.
- 설정 교체 API가 잘못 노출되면 외부에서 서비스 동작을 바꿀 수 있다 → 로그인 뒤에만 노출한다.

**후속 작업**

- 시나리오 5종 YAML 작성과 디코이 변경 포함 (T3-02)
- 트래픽 생성기(고정 질문 집합·rps·시드) 구현 (T1-15)
- 설정 교체 엔드포인트를 인증 뒤로 제한하고 변경을 이력에 기록
- 주입 실패 시 해당 회차 데이터를 폐기하는 처리 추가

## 옵션별 장단점

### 옵션 1 — 코드 수정 + 재배포

- 장점: 어떤 변경이든 자유롭게 넣을 수 있다.
- 단점: 반복 실험 비용이 크고 주입 시점이 정확하지 않아 정답 라벨의 시간 정밀도가 떨어진다.

### 옵션 2 — Git 커밋 + 재배포

- 장점: 실제 운영에서 일어나는 변경 흐름과 가장 가깝다.
- 단점: 50회 반복에 적합하지 않고, 배포 소요 시간이 탐지 지연 측정에 섞인다.

### 옵션 3 — YAML + 런타임 교체 (채택)

- 장점: 정답 라벨·재현성·시연 편의를 모두 확보한다.
- 단점: 배포 부수 효과를 재현하지 못하고, 교체 경로의 접근 통제가 필요하다.
